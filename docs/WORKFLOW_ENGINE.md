# Execution and recovery

`Runtime.start` initializes local defaults and captures referenced definitions. `tick` advances its configured burst of at most 100 nodes per slice and returns a new immutable execution, side effects and scoped values. `Coordinator.drive` runs at most five slices before enqueueing another worker. Terminal states are COMPLETED/CANCELLED/FAILED/EXPIRED. Human, time and condition waits contain durable tokens/deadlines/continuation frames and do not retain a thread.

Room stores the complete snapshot, current state, event identity and next wake time. One coordinator Mutex serializes platform operations within the app process, and Room transactions atomically commit execution, variable changes and outbox effects. No separate process is configured. Duplicate event keys have a unique database index. Duplicate/late responses cannot transition a consumed or expired interaction. Each notification action uses an explicit immutable PendingIntent with execution ID, unpredictable token and option identity.

Outbox draining occurs after commit. Each interaction uses an owned execution/token notification tag, so concurrent branch questions coexist and response/snooze/expiry removes only the matching question. Informational messages have a separate tag so workflow completion does not immediately remove them. A crash after posting but before deleting an outbox row may re-post the same tag. This is effectively-once display, not a universal exactly-once side-effect guarantee. Workflow effects are limited to local notifications and variables.

Parallel branches are embedded executions in the parent snapshot, with durable round-robin position and the earliest child/parent wake. They do not create background threads or additional Room rows. Human responses search the snapshot tree by token. JOIN merges isolated local writes, rejects conflicts and propagates child failures to the parent TRY boundary. All child work contributes to the parent's step budget; see WORKFLOW_LANGUAGE.md for limits. New execution rows use an aborting INSERT so secondary event-key conflicts cannot be silently swallowed by Room's upsert fallback. Snapshot JSON preserves a null cursor at end-of-stack, including after a final response or final wait.

On boot, upgrade, clock/timezone changes and foreground entry, reconciliation calculates next alarms, restores execution wakes and registers geofences. A unique periodic WorkManager job performs deferrable recovery. Force-stop prevents delivery until the app is reopened. Permissions and platform failures are visible in Settings/diagnostics; denied notifications leave human interactions accessible in Activity.

Concurrency defaults: four active runs per automation, 32 globally, visible refusal when exceeded. Manual starts are explicit and permitted for disabled workflows. Automatic starts require enabled state and configured cooldown. Configured parallel/ignore/queue/replace policies and one-to-four active instances apply per automation. Queues are bounded within the global total and promoted by priority. Frequency policies include cooldown, daily, weekly, entry session, completion and unlimited subject to safety limits.

Geofence registration reuses a persisted fingerprint for unchanged healthy configurations, invalidating on boot/update/errors and permission/service changes. Location transition history and a durable event ledger survive execution pruning. Snapshot/resource overflow yields a compact FAILED record and cancellation effect, preserving prior persistent values. Message capacity and denial are diagnostic; human truth remains in Activity.
