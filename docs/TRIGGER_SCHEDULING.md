# Trigger scheduling

Time schedules support daily, selected weekdays/weekly, monthly (clamped to month's last day), selected dates/once, anchored N-day intervals, multiple clock times and inclusive start/end dates. The next occurrence alone is scheduled. `device` follows the device timezone; explicit IANA zones remain fixed. Android API 29 provides java.time.

DST gaps move forward by the gap; ambiguous local times use the earlier offset. Clock and timezone receivers reconcile schedules. Exact AlarmManager access is checked on API 31+; revocation/security errors fall back to `setAndAllowWhileIdle`. WorkManager provides a durable deferrable fallback. Although alarm delivery can be exact, execution is delegated to workers and may be delayed. Neither periodic recovery nor geofencing is an exact timing guarantee.

Daily, weekly and monthly windows use stable local-calendar boundaries in the selected timezone, with end-exclusive identities. Weekly windows start on WINDOWDAY at the first configured clock time and end one week later. Stable keys deduplicate original delivery and permitted catch-up. Recovery evaluates the current window, so Friday delivery missed and recovered Sunday remains eligible. Non-window recovery uses the original occurrence identity. Grace defaults to one hour. `skip` does not start catch-up; `grace` permits recovery within grace; `window` permits catch-up inside the current window. `ask` creates a durable yes/no interaction with a one-hour deadline: Yes proceeds, No stops. A separate event ledger records starts and missed-event outcomes, preserving deduplication after execution-history pruning. Delivery checks definition version and occurrence identity even after reconciliation schedules the next occurrence.

Location monitoring uses Google Play Services enter/exit/dwell events, minimum radius 100 m, maximum 100 registered locations, configurable dwell (30–86,400 seconds), cooldown (0–86,400 seconds), two-minute responsiveness hints and no fabricated initial event. Registration status follows the bounded API result. Unchanged registration fingerprints avoid repeated registration; reboot, package updates, invalid registration and relevant permission/service changes require reconciliation. Missing precise/background permissions, disabled location or unavailable Play Services produce visible failures. Occupancy starts UNKNOWN and expires after one hour. Cooldown and stable event keys suppress repeat starts. Location triggers apply DAYS, ZONE, START/END dates and optional ELIGIBLEFROM/ELIGIBLETO local clock times. Both clock fields must be supplied together; blank or equal times mean all day, otherwise the end is exclusive. In overnight windows, the after-midnight portion belongs to the starting day/date (Friday 22:00–02:00 includes Saturday 01:00). Occupancy updates even when an event is outside workflow eligibility. Physical delivery timing requires final phone verification.
