# Workflow language v1

Blockly JSON is editor state. `Compiler.compile` creates `Definition(schema=1, id, version, entry, nodes, variables, trigger, budgets)`. Nodes have stable block IDs, an allowlisted operation, string configuration fields, typed expression trees, named branches and an optional next node. Definitions are structured data; neither generated JavaScript nor Kotlin is executed.

Values are Boolean, Integer, Decimal, String, Instant (epoch milliseconds), Duration (milliseconds), List or Null. Literal timestamps use ISO 8601; duration fields use seconds. Strings are capped at 16,384 characters; list operations cap lists at 1,000 items. Explicit conversions are available. Numeric strings do not participate in arithmetic without conversion. AND/OR short-circuit; other binary expressions evaluate their required inputs.

Declare variables with a scope and type before reading or writing them. Blank defaults mean null. Response variables are local; use SET to persist them. Automation values belong to the currently executing definition ID; global values belong to `global`. Local values are isolated between calls; input and return values pass by value.

Statement stacks compile to acyclic next/branch edges. Guarded loop nodes introduce repetition through durable frames. Trigger budgets configure maximum steps (1–10,000), loop iterations (1–1,000), burst size (1–100), CALL depth (1–8) and notification frequency (1–120 per minute). Budget timestamps persist across waits and are shared by calls/parallel branches. Imported IR is never accepted as authoritative: backups import workspaces and recompile them natively.

IF branches are YES/NO. Choice blocks have independently persisted CHOICE0…CHOICEn branches, with legacy first/second/other fallback. Yes/no and text/number blocks use YES/NO and valid-input semantics. All interactions have CANCEL/TIMEOUT branches. Checklist entries beginning with `?` are optional. Missing action branches continue to the next statement. Timeout with no branch expires the execution.

CALL supports up to 20 named expression inputs, named local output mappings and a local STRING status result. The legacy single input/result binding remains supported. Target definitions and their transitive dependencies are snapshotted when an execution starts. RETURN with no value returns Null. Reaching the end returns to the caller without overwriting its output variable. CALL depth is configurable from one to eight; recursive dependencies are rejected. Disabling an automation stops new automatic starts; existing snapshots continue. Deleting an automation removes its own runs and is prevented when another saved automation calls it.

PARALLEL advances A and B in a deterministic round robin, one statement at a time. A wait or question suspends its branch while the sibling continues. Both must complete before JOIN continues the parent. Locals start as independent copies; JOIN merges changed names and rejects different writes to the same name (equal writes are allowed). Automation/global writes share the transaction's ordered value map. Branch snapshots include frames, captured definitions, deadlines and independent response tokens. Nesting is limited to 16 and at most 64 branch executions; the parent step budget includes child work. BREAK/CONTINUE cannot cross a parallel boundary. A failed/expired branch fails the join and cancels sibling interactions; an enclosing TRY can handle that failure. Parent cancellation/deadline rejects every child response and cancels owned questions.

TRY handles errors with a visible trace and resumes the handler. STOP completes the current execution/branch. Breakpoints record a trace marker in production and pause simulation after the marker. WAIT CLOCK chooses the next strictly future clock time in its selected zone. SET TIMEOUT sets a persisted overall deadline from the current time, caps subsequent wakes and rejects responses after expiration. JSON preserves explicit null cursors, and a missing legacy cursor means end-of-stack; it never implicitly restarts the entry node.

Typed lists use the LIST constructor and optional element type on declarations; updates enforce item types. Checklist templates are captured per run. Location expressions return saved coordinates/radius, last entry/exit/dwell and current dwell duration; stale or contradictory occupancy remains UNKNOWN. Library, snapshot and aggregate value limits fail visibly before publishing new effects/values; see KNOWN_LIMITATIONS.md.
